# Заметки об обновлениях Iris

Окно «Что нового» рассказывает человеку, что изменилось и где это попробовать.
Записи пока публикуются по-русски; при английском интерфейсе переводятся кнопки
и навигация, а авторский текст сохраняется целиком на языке записи.
Запись читается за минуту: одно главное изменение, несколько понятных пунктов,
при необходимости — скриншот. Это редакторская работа, а не экспорт git log.

## Где живут записи

- [`apps/web/src/changelog/releases/`](../apps/web/src/changelog/releases/) — один TypeScript-файл на версию; каталог подхватывает его автоматически.
- [`types.ts`](../apps/web/src/changelog/types.ts) — контракт, включая необязательные изображения.
- [`VERSION`](../VERSION) — установленная версия. Каталог интерфейса читает её напрямую при сборке.
- [`CHANGELOG.md`](../CHANGELOG.md) — общий перечень изменений репозитория. Согласуй с ним факты, но перепиши технические пункты для читателя приложения.

В каталоге видна текущая сборка и более ранние записи со статусом `released`.
Будущие версии и чужие черновики не показываются. Версии сортируются по SemVer,
включая кандидаты вида `1.1.0-rc.2`. Старые записи не удаляются.
Сейчас существует только целевая неопубликованная `1.0.0`: не придумывай ранние выпуски ради заполнения списка.

## Как написать

1. Проверь изменение в коде и результаты его проверки. Выбери 3–7 заметных для
   пользователя изменений. Изменение зависимости обычно не требует отдельного пункта.
2. Сначала назови результат: «Напоминание можно перенести», затем дай одну
   конкретную деталь: «Выберите другое время в карточке плана».
3. Придумай короткий заголовок выпуска. Он может быть с характером, но должен
   помогать понять содержание: «Нужное легче найти», «Меньше потерянных мыслей».
4. Для уведомления напиши отдельную фразу `summary` до 90 знаков.
   Она должна объяснять, зачем открывать подробности, без перечня всех изменений.
5. Выдели одно главное изменение в `highlight`. Остальные сгруппируй по смыслу:
   «Появилось новое», «Стало удобнее», «Поправили». Пустые группы не нужны.
6. Если человеку нужно что-то сделать после обновления, вынеси это в `note`:
   какое действие, где выполнить и почему. Существенное ограничение тоже укажи здесь.
7. Прочитай вслух. Сократи фразы, которые звучат как отчёт агента или рекламный текст.

### Голос и точность

Пиши по-русски, спокойно, живо и конкретно. Небольшая игра слов допустима в
заголовке; объяснение функции должно оставаться ясным. Не превращай заметку в
реплику от лица Iris и не используй фамильярность без причины.

| Вместо | Лучше |
| :--- | :--- |
| «Реализована персистентность уведомления» | «Уведомление останется, пока вы его не закроете» |
| «Оптимизирован UX навигации по сущностям» | «Разговор, факт или план можно найти из одной строки поиска» |
| «Мы рады представить революционное обновление» | Название конкретной новой возможности |
| «Улучшены производительность и стабильность» | Какое заметное ожидание или сбой исправлены |

Не используй «осуществляется», «в рамках», «бесшовный», «инновационный»,
«выводит на новый уровень» и обещания «теперь всегда» без доказательств.
Не перечисляй названия классов, миграций, commit hash и внутренние протоколы.
Не заявляй о проверке микрофона, Windows-установщика или аватара на основании
успешной веб-сборки. Не называй обновление опубликованным, если подготовлены
только исходники. Планы выноси из основного списка возможностей.

## Шаблон записи

Создай файл с точным номером версии, например `1.1.0.ts`. Пример ниже —
шаблон будущего изменения, а не существующий выпуск; перепиши его по проверенным фактам.

```ts
import type { ReleaseNote } from "../types";

export default {
  version: "1.1.0",
  status: "preview", // released — только после подтверждённого выпуска
  // date: "2026-11-10", // только фактическая дата публикации
  title: "Нужное легче найти",
  summary: "Разговоры и заметки — ближе. Посмотрите, что изменилось в поиске.",
  intro: "Короткое вступление о том, для чего пригодится это обновление.",
  highlight: {
    label: "Главное в обновлении",
    title: "Одно заметное изменение",
    description: "Что теперь можно сделать и где это найти.",
  },
  sections: [{
    kind: "improved", // new | improved | fixed
    title: "Стало удобнее",
    items: [{ title: "Понятное название", description: "Конкретная польза в одном-двух предложениях." }],
  }],
  // note: "Действие после обновления или существенное ограничение.",
} satisfies ReleaseNote;
```

`preview` означает, что выпуск ещё в разработке. Не задавай ему дату будущей
публикации. Перед выпуском согласуй версию по [правилам версий](versioning.md),
проверь текст на финальной сборке и обнови статус с датой только после
подтверждения выпуска. Новая запись для той же версии не создаётся.

## Изображения

Изображение можно добавить к `highlight` или к отдельному пункту через `image`:

```ts
image: {
  src: "/changelog/1.1.0/search.webp",
  alt: "Окно поиска с результатами из истории и памяти",
  width: 1280,
  height: 800,
  caption: "Откройте поиск сочетанием Ctrl+K.",
},
```

Положи файл в `apps/web/public/changelog/<version>/`. Используй настоящий
скриншот этой версии, схему с ясной подписью или уместное фото с правом
распространения. Скриншот обрежь до нужного фрагмента. Удали личные сообщения,
ключи, пути профиля и другие частные сведения. Чужие исходные модели аватара
и закрытые ассеты в каталог не добавляй.

Предпочитай WebP/PNG; SVG и короткий GIF допустимы, если действительно нужны.
Избегай декоративных анимаций и мерцания. Ширина до 1600 px и размер до 500 КБ
обычно достаточны. `alt` описывает содержание, `caption` объясняет пользу.
Укажи реальные `width`/`height`, чтобы изображение не сдвигало текст при загрузке.
Внешние URL, HTML, iframe и скрипты не поддерживаются. Все материалы входят
в сборку и доступны без интернета; отсутствие картинки — нормальный вариант.

## Когда появляется уведомление

После запуска оболочки и завершения первоначальной настройки появляется
уведомление для ещё не прочитанной установленной версии. Оно не имеет таймера.
«Что нового» открывает центрированное окно с отдельными подложками шапки и
содержимого, как в поиске; крестик закрывает уведомление.
Оба действия подтверждают прочтение. Открытие из Настройки → Что нового тоже
подтверждает его. Если просто выйти из приложения, уведомление вернётся при
следующем запуске. Повторные запуски прочитанной версии его не показывают.

Флаг хранится в `localStorage` (`iris.changelog.acknowledged.v1`) отдельно от
истории диалога и памяти. Очистка данных сайта/профиля сбрасывает его; при
запрете записи в хранилище подтверждение действует до конца сеанса.
Автообновление и скачивание файлов эта система не выполняет.

## Проверка перед сдачей

Для работы над текстом запусти `npm --prefix apps/web run dev` и открой
`http://127.0.0.1:5173/changelog-preview.html`. Это тот же компонент окна и
текущая запись, без ядра, микрофона и загрузки моделей. Кнопка на странице
показывает пример уведомления. Страница включается только в разработку и
сборку `preview-tools`; обычная продуктовая сборка её не содержит.

```powershell
npm --prefix apps/web test -- src/changelog/catalog.test.ts src/changelog/notice.test.tsx src/components/Changelog.test.tsx
npm --prefix apps/web run build
```

Проверь текущую запись, порядок версий, отсутствие дубликатов и существование
изображений. Открой уведомление и историю в узком и широком окне. Проверь
Escape, клавиатуру, возврат фокуса, длинный текст и прокрутку. Переключись на
старую версию, закрой окно и открой снова — выбранной должна стать установленная.
При нескольких ещё не прочитанных версиях уведомление одно, для установленной;
остальные доступны через список. Для проверки обновления меняй версию только
в изолированном тесте, не очищай пользовательский профиль и его хранилище.

# Инструкция агенту: сборка Iris и будущего установщика

Передача от 24 октября 2026 года. Это исходная точка для следующей задачи
по сборке приложения и установщика. Перед выполнением команд проверь текущие
скрипты, состояние репозиториев и новые указания владельца.

## Решения владельца

- `bad1and/NeuroAsist` остаётся публичным с прежним адресом. Рабочая ветка
  после очистки — `v0.9.1`; версия продукта берётся из `VERSION` (сейчас `1.0.0`).
- В закрытом `Gogowski/NeuroAsist-avatar-private` находятся исходный VRM,
  ограниченные анимации, производные ресурсы и workflow сборки **только Unity**.
  Код Unity берётся из проверенного полного SHA публичного репозитория.
- Приложение и будущий установщик собираются публично из открытого кода
  и готового Unity Player. Пользователь в итоге скачивает готовый установщик
  из публичного GitHub Releases; отдельные токены и сборка Unity ему не нужны.
- Исходные `.vrm`, `.glb`, `.gltf`, частные FBX и производные исходные ассеты
  не должны попадать в публичное дерево, новые commits, artifacts или установщик.
  В поставке допустимы скомпилированные ресурсы Player.
- **Остаточный доступ через старые служебные PR refs принят владельцем.**
  Он не блокирует подготовку и выпуск установщика. Не требуй обращения
  в GitHub Support и не начинай новую очистку истории ради этих ссылок без
  отдельного поручения. Не называй исходник полностью недоступным.
- Дополнительное шифрование, DRM и защита от извлечения из Unity сейчас
  не требуются. Не обещай абсолютную неизвлекаемость. Это решение об объёме
  технической защиты; оно не меняет условия сторонних компонентов.

## Что уже готово и что ещё проверить

Есть инструменты импорта закрытых входов, упаковки Player и проверки SHA-256,
digest исходников и файлов пакета. Обычные ветки публичного репозитория очищены;
свежий clone не содержит исключённых ресурсов в доступной истории веток.
Исходная история и рабочие файлы сохранены в локальных резервных копиях.

Локальная изолированная Unity-сборка и проверка пакета из 151 файла прошли.
Также прошли 56 целевых Python-тестов, веб-сборка, Rust check и публичная
проверка границы исходников. **Вся цепочка Actions и готовое приложение с этим
пакетом ещё не приняты; установщик не создавался.** Подробности и хеш ранее
проверенного компонента — в [результате перехода](avatar-distribution-result-2026-10-24.md).
Для нового выпуска проверяй соответствие текущим исходникам, не считай старый
хеш универсальным.

## Подготовка доступа

1. Проверить доступ к закрытому репозиторию: `bad1and` приглашён с правом записи.
2. Настроить Windows runner **только закрытого** репозитория с метками
   `self-hosted`, `Windows`, `iris-avatar-private`. Нужны PowerShell 7, Git,
   Python 3.12, лицензированный Unity 2022.3.62f3 и Windows Build Support (Mono).
   `NEUROASIST_UNITY_EDITOR` указывает на `Unity.exe` и виден процессу runner.
3. Создать fine-grained token только для `Gogowski/NeuroAsist-avatar-private`
   с разрешением **Actions: read**. Сохранить в Secrets публичного репозитория
   как `IRIS_AVATAR_ARTIFACT_READ_TOKEN`. Настройка оставлена второму разработчику
   по просьбе владельца; сначала проверь, не выполнена ли она уже. Токен
   в чат не запрашивать; широкий личный PAT для этого не использовать.
4. Настроить environment `release-candidate` и ограничить доступ проверенными
   разработчиками и refs. Публичные PR не должны запускаться на частном runner.

## Последовательность работы

1. Использовать свежий checkout очищенной истории. Старый рабочий каталог
   на `v0.9` нельзя пушить или сливать обратно. Несвязанные рабочие изменения
   сохранять; для сборки нужен отдельный чистый checkout выбранного commit.
2. Выполнить `python scripts/avatar_assets.py check-public` и проверку
   документации `python scripts/check_docs.py`. Не импортировать VRM в публичный
   checkout сборки приложения. Все частные входы остаются в закрытой Unity-сборке.
3. В закрытом Actions вручную запустить `Build private Iris Unity Player`
   с полным 40-символьным SHA проверенного публичного кода. Сохранить run ID,
   SHA-256 внутреннего `iris-avatar-windows.zip` и данные исходников.
   Внешний скачанный Actions ZIP имеет другой хеш. Проверенный хеш компонента
   брать из доверенного результата частной сборки.
4. В публичном Actions запустить `Build Windows application candidate` с SHA
   приложения, private run ID и SHA-256 Player. Сейчас workflow выпускает
   **AppOnly**, без NSIS и Release. Проверить приложение по
   [приёмке перед установщиком](preinstaller-readiness.md).
5. Затем подготовить отдельный публичный этап NSIS, используя тот же способ
   передачи Player и существующий `build-desktop-release.ps1`. Не возвращать
   локальную Unity-сборку с VRM в публичный job и не обходить проверки пакета.
6. Пройти установку, первый запуск, обновление и удаление на чистой Windows;
   проверить аватар, голос, ресурсы и сохранность пользовательских данных.
   Выполнить применимые условия [порядка выпуска](release-runbook.md) и
   [checklist](release-checklist.md), включая существующие вопросы TTS/FFmpeg.
7. Для разрешённой задачи публикации выложить установщик, контрольную сумму
   и манифест в публичный Release; связать их с точным commit и версией.
   Не включать сырые входы или частный checkout в публикуемые artifacts.

Публичный workflow уже имеет ручную точку входа в `main` и собирает выбранный
SHA. Режим NSIS и публикацию ещё предстоит добавить; одного запуска текущего
workflow для получения установщика недостаточно.

## Команды с готовым Player

Из корня чистого checkout с подготовленным окружением проекта:

```powershell
# Сначала каталог приложения для приёмки:
.\scripts\build-preinstaller-app.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<проверенный SHA-256 компонента>' `
  -ArtifactDirectory artifacts\preinstaller

# Позже NSIS, после подготовки остальных компонентов выпуска:
.\scripts\build-desktop-release.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<проверенный SHA-256 компонента>' `
  -ArtifactDirectory artifacts\installer
```

Для подписанной поставки используется `-SigningCertificateThumbprint`.
Без подтверждения подписи не объявляй артефакт подписанным. `-ReuseCore` и
`-SkipDependencyInstall` не использовать для нового кандидата без проверки
соответствия окружения. Изменения Unity-кода, протокола или версии могут
потребовать нового компонента. Actions artifacts живут 30 дней: для выпуска
предусмотри долговременное хранение проверенного Player.

## Что сохранить в отчёте

Запиши SHA приложения и частных входов, run IDs, версию Unity, хеш Player,
`avatar-component.json`, хеш установщика, статус подписи и реально выполненные
проверки. Проверь установленный каталог: исходных моделей и частных входов нет,
notices и credit Kado присутствуют. Успешная компиляция не заменяет проверку
запуска и установки. Отдельно перечисли то, что осталось непроверенным.

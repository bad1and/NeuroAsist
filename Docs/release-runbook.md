# Порядок выпуска

Этот порядок создаёт проверяемого кандидата. Решение о публичной публикации
принимается после [условий выпуска](release-checklist.md).
Номер `1.0.0` в исходниках сам по себе не подтверждает готовность установщика.

Агенту, продолжающему подготовку установщика, сначала прочитать
[инструкцию передачи](installer-agent-handoff.md): в ней зафиксированы
раздельная сборка и принятый владельцем остаточный доступ через старые PR refs.

Подготовка до установщика объединена в [три крупных этапа](release-stage-2-plan.md).
Перед сборкой сверить [разбор зависимостей](security-dependencies-2026-10-20.md)
и [условия материалов](../THIRD_PARTY_ASSETS.md). Для следующего каталога
подготовлена отдельная [карточка кандидата](release-candidate-next.md).

Для TTS/FFmpeg принят [план поставки без ручной настройки пользователем](tts-ffmpeg-delivery.md).
При упаковке notices готовятся для обоих режимов. AppOnly записывает диагноз
FFmpeg; NSIS требует соответствия выбранному профилю и сейчас остановится
на прежнем wheel с x264/x265. Сначала подготовить и проверить новый PyAV wheel
по `third-party/ffmpeg/profile.json`; успешная проверка флагов не заменяет
поставку соответствующих исходников и выполнение остальных условий лицензии.

## Каталог приложения без установщика

```powershell
.\scripts\build-preinstaller-app.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<SHA-256 из доверенной закрытой сборки>' `
  -ArtifactDirectory artifacts\preinstaller
```

Unity собирается отдельно в закрытом репозитории по
[схеме поставки аватара](avatar-distribution.md). Команда проверяет готовый Player
и готовит CPU Python onedir и Tauri `--no-bundle`. Дополнительные
ресурсы передаются отдельным override; исходный Tauri-конфиг не переписывается.
Каталог `iris-1.0.0-app` содержит приложение, ядро, аватар, notices и SHA-256.
Снимок исходников до и после сборки должен совпадать. Незакоммиченные изменения
отражаются в манифесте; финальный кандидат следует собирать с `-RequireCleanWorktree`.
`-SkipAvatarBuild` использует ранее проверенный Unity player.
`-SkipDependencyInstall` допустим только для уже проверенного release-окружения.

При смене pins нельзя переносить результаты со старого ядра через `-ReuseCore`.
Для финального кандидата собрать свежее ядро и Unity; при обоснованном повторном
использовании отдельно подтвердить соответствие хешей текущим исходникам.

Пройдите [приёмку приложения](preinstaller-readiness.md) на этом каталоге.
Установка, подпись, обновление и удаление ниже остаются следующим этапом.

## Подготовить исходники

1. Согласуйте [версию](versioning.md), изменения и миграции.
2. Пройдите проверки из [эксплуатации](operations.md#проверки-изменений).
3. Создайте [карточку сборки](release-evidence.md): commit, среда и ожидаемые артефакты.
4. Сборку выполняйте из чистого рабочего дерева. Не включайте локальные данные,
   ключи, кэши и результаты экспериментов.

## Автоматические подтверждения

| Workflow | Запуск | Результат |
| :--- | :--- | :--- |
| `Documentation` | PR и `main` | Версии, параметры окружения, локальные ссылки и изображения |
| `CI` | PR и `main` | Backend pytest, Vitest/build и Windows Rust check |
| `Synthetic lifecycle soak` | Еженедельно и вручную | Одночасовой отчёт состояний, отмены и роста памяти |
| `Public avatar source boundary` | PR, `main`, `v0.9.1` | Запрет исходных моделей и частных анимаций в публичном дереве |
| `Build Windows application candidate` | Вручную с private run ID и SHA-256 | Каталог приложения AppOnly с проверенным Unity Player; без NSIS и публикации |

Конфигурации находятся в [`.github/workflows`](../.github/workflows/).
Синтетический прогон не использует микрофон, загрузку моделей или Unity.

## Подготовить Windows-runner

Публичный workflow приложения работает на `windows-latest`. Только закрытая
Unity-сборка использует self-hosted runner `Windows`, `iris-avatar-private`
с лицензированным Unity Editor. `NEUROASIST_UNITY_EDITOR` указывает на его EXE.
Публичной сборке нужен `IRIS_AVATAR_ARTIFACT_READ_TOKEN` с разрешением
Actions read только для `Gogowski/NeuroAsist-avatar-private`.

В GitHub используется environment `release-candidate` с принятой в проекте
политикой проверки. Для подписи сертификат устанавливается в хранилище Windows
runner; его отпечаток задаётся секретом `WINDOWS_CERTIFICATE_THUMBPRINT`.
Необязательная переменная `WINDOWS_TIMESTAMP_URL` выбирает сервер отметки
времени. По умолчанию сценарий использует сервис DigiCert.

Workflow не создаёт установщик или GitHub Release и не объявляет сборку стабильной.
Автоматический запуск сборки установщика по тегу на этом этапе отключён.

## Собрать кандидата

После получения проверенного пакета из закрытой Unity-сборки, из корня репозитория:

```powershell
.\scripts\build-desktop-release.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<проверенный SHA-256 компонента>' `
  -ArtifactDirectory artifacts
```

С подписью:

```powershell
.\scripts\build-desktop-release.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<проверенный SHA-256 компонента>' `
  -SigningCertificateThumbprint 'ОТПЕЧАТОК_СЕРТИФИКАТА' -ArtifactDirectory artifacts
```

Замените отпечаток на значение из хранилища сертификатов.
Сценарий проверяет запрошенную Authenticode-подпись и ядро с включённым токеном.

Базовый установщик использует CPU-профиль. CUDA DLL удаляются из генерируемого
ядра перед упаковкой; GPU-поставка должна квалифицироваться отдельно.
Большой CUDA PyTorch runtime также создаёт риск превышения лимита NSIS.

## Зафиксировать результат

В игнорируемом каталоге `artifacts/` появляются:

- NSIS-установщик;
- `iris-<version>-release-manifest.json` с SHA-256, commit, размером и статусом подписи.

До NSIS `scripts/check_release_artifact.py` проверяет дерево Python-ядра и
Unity-ресурсов на `.env`, SQLite и частные файлы. Манифест отражает именно
проверку ресурсов **до упаковки**, а не разбор содержимого готового NSIS.

Сохраните артефакты workflow и отчёты вместе. Пересборка требует нового хеша.
Установщик, манифест, commit и тег относятся к одному набору подтверждений.

Обязательные LICENSE/PRIVACY/THIRD_PARTY_ASSETS, `licenses/` и
`THIRD_PARTY_NOTICES.txt` проверить именно в установленном каталоге NSIS.
Их наличие в AppOnly-кандидате не доказывает включение в установщик.
Для FFmpeg сверить DLL с соответствующими исходниками и условиями поставки.

## Пройти ручные проверки

Заполните разделы карточки сборки:

1. чистая Windows: установка, первый запуск, обновление и удаление;
2. восстановление данных и обработка повреждённой базы;
3. час реального микрофона с аватаром, переподключением и перебиванием;
4. память, характер и 30-минутный расход LLM;
5. лицензии, конфиденциальность, секреты и границы Coding Agent.

Заранее запишите пороги и оборудование. Отчёт без выполненного сценария
не закрывает проверку. Условия измерения задержки — в [голосовой задержке](voice-latency.md).

## Одобрить и опубликовать

Ответственный за выпуск сверяет checklist и карточку, записывает решение и
известные ограничения. Для стабильной версии нужны подтверждённая подпись,
контрольная сумма и понятный путь отката. До этого кандидат остаётся внутренним.

Откат должен учитывать совместимость базы: понижение бинарной версии после
миграции нельзя считать безопасным без проверки. Сохраните предмиграционный
снимок и протестированную предыдущую сборку.

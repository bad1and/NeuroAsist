# Проверка фактов в разговоре

Iris использует бесплатные источники без ключей по умолчанию. Поиск, чтение
страницы и ответ — отдельные операции. История хранит их фактический результат;
персонаж не должен выдавать знания модели или старый кэш за новое обращение.

## Когда начинается проверка

Прямые просьбы найти или проверить информацию и вопросы о текущих событиях
обрабатываются до генерации ответа. Короткое продолжение восстанавливает тему
из последних пользовательских реплик и метаданных текущей сессии.
Приветствие, смена темы, личная беседа и запрет интернета прекращают наследование.

Ясный запрос собирается правилами. Неоднозначная явная просьба может использовать
один ограниченный структурированный вызов планировщика. Если предмет не удалось
определить, Iris уточняет его. Это не означает недоступность поисковика.

Уточнения и повторные попытки ограничены общим дедлайном и бюджетом.
Служебные LLM-вызовы входят в общий расход ответа.

## Источники

| Источник | Назначение |
| :--- | :--- |
| DuckDuckGo HTML и Bing RSS | Бесплатная веб-выдача |
| Google News RSS | Тематический поиск недавних событий |
| Официальная Steam RSS-лента Deadlock | Полные тексты анонсов разработчика для вопросов о героях и релизах |
| RSS/Atom-ленты | Фоновые новости по категориям `general`, `tech`, `science`, `games` |
| MediaWiki API | Дополнительные сведения для биографических запросов |
| Tavily | Необязательный пользовательский поисковый API с проверкой бесплатного тарифа |

HTTP `200` не подтверждает соответствие вопросу. Проверяются сущность,
версия, дата и содержание. Официальный домен повышает доверие после проверки
темы. Сниппет и прочитанная страница отмечаются отдельно.
Дата статьи не является доказательством даты описанного события.

Для релизов оценка `sufficient` требует точной цитаты из прочитанного источника.
Старое расписание не подтверждает состоявшийся выход, а соседние имена в списке
не считаются именами одного персонажа. Для известных продуктов сначала проверяется
домен разработчика; пользовательские темы форума не считаются первоисточником
только из-за домена. Для Deadlock читается официальная Steam-лента, включая
текст объявления, а не только заголовок или сниппет.

Свежие объявления имеют приоритет перед устаревшими гайдами. Для утверждения
«последний сейчас» недатированный материал или материал старше недели сам по
себе недостаточен. Если цитата отвергнута как анонс будущего релиза, причина
передаётся следующей оценке. Составной вопрос допускает отдельные цитаты из
нескольких публикаций. В истории сохраняются `supporting_quote` и
`evidence_warnings`; оценка достаточности остаётся проверкой сведений, а не
гарантией безошибочного пересказа моделью.

Повторная просьба «ещё раз» обходит кэш, в том числе при native tool calling.
Два или три связанных вызова `web_search` могут объединяться в один поиск
после проверки всех аргументов, с прежним общим бюджетом. Несвязанные,
некорректные и смешанные с действиями вызовы не исполняются частично.

Для итогов выборов и соревнований предварительные материалы не считаются
окончательным результатом. Если сведений недостаточно, это отражается в ответе.

## Пределы операции

| Ограничение | Текущий профиль |
| :--- | :--- |
| Общий дедлайн подготовки и получения сведений | 15 секунд |
| Смысловые запросы на ход | До 3 |
| Поисковые обращения и чтение страниц | До 6 суммарно |
| Прочитанные страницы | До 3; часть бюджета сохраняется для уточнения |
| Источники обычного ответа / новостей | До 3 / до 7 |
| Кэш справки / новостей / ошибки | 5 минут / 1 минута / 30 секунд |
| Пауза повторных обращений после блокировки | 1 минута |
| Размер произвольной страницы | До 512 КБ |

Источники могут менять разметку и ограничивать обращения. Явный повтор обходит
кэш результата, но сохраняет паузу после блокировки. Одинаковые запросы
объединяются; отмена одного ожидающего не отменяет работу для остальных.
Ходы с собственным бюджетом или уведомлениями выполняются отдельно, чтобы
не использовать дедлайн и события соседнего разговора; готовый кэш общий.

Известный домен первоисточника используется уже в первом бесплатном запросе.
При слабой выдаче поиск расширяется. Период передаётся бесплатным поисковикам
с запасом в один день, а точные границы и часовой пояс проверяются по датам
публикаций после получения выдачи и чтения страниц. Более полная прочитанная
копия URL заменяет короткий сниппет того же адреса.

Если первый бесплатный поисковик не ответил за 350 мс, обычный запрос без
ограничения домена или периода может запустить один бесплатный запасной
источник. Подходящий ответ завершает ожидание; более медленное обращение
отменяется и отмечается в истории. Быстрый первый ответ не запускает запасной.
Проверки релизов, итогов событий и платные API сохраняют последовательный путь.

Допускаются публичные HTTP(S)-адреса и стандартные порты. Перенаправления
проверяются; соединение закрепляется за проверенным IP. Внешние страницы
не становятся инструкциями для модели.

## Что можно честно сказать о поиске

| Метаданные | Значение |
| :--- | :--- |
| `invalid` | Корректный запрос не сформирован; сетевого поиска не было |
| `cached: true` | Использован ранее полученный результат |
| `empty` | Подходящие сведения не найдены |
| `blocked`, `timeout`, `error` | Разные причины незавершённой проверки |
| `sufficient`, `partial`, `none` | Оценка достаточности сведений, а не гарантия истины |

Прошлый статус не доказывает состояние инструмента сейчас.
Вопрос о том, что Iris искала, должен опираться на журнал поисковых операций.
Кэш не считается новым обращением; некорректный запрос не считается сетевой ошибкой.

До сохранения и озвучки ответ проверяется на выдуманные действия и пустые
обещания «проверю». Допускается ограниченное исправление по уже полученным
данным. Оно не должно создавать новый поиск без основания.

## Ожидание и уведомления

Если операция задерживается, Iris может один раз дать короткую реплику,
подходящую текущему разговору. Фиксированного обязательного «секунду, проверю»
нет. Быстрое завершение, отмена или использование кэша не требуют объявления.

`retrieval.progress` передаёт этапы `searching`, `reading`, `refining`,
`finished` с принадлежностью к сессии и ходу. Поисковые уведомления
(`web_search_notifications_enabled`) по умолчанию выключены.
При включении карточка отражает живую операцию; старые события после
переподключения не должны создавать новую карточку. Новый ход и отмена закрывают
старую. Подробности результата сохраняются в истории независимо от уведомлений.

## Новости и продолжение темы

Ленты обновляются в фоне после готовности чата. TTL источника — 15 минут,
одновременно загружаются четыре ленты. Выключение новостей прекращает новые
фоновые загрузки. Состояние каждой ленты включает результат загрузки и дату.

Тематическая подборка ограниченно ожидает фоновые данные и при необходимости
дополняется поиском. Статьи дедуплицируются. Свежая RSS-подборка не включает
статьи без даты; старые материалы требуют явного периода.
Устаревший кэш помечается `stale`.

«Ещё новости» использует тему, период и уже показанные события последнего ответа
в текущей сессии. Новая тема или другая сессия не продолжают прежнюю подборку.
«Вчера» и «сегодня» вычисляются по местному времени Windows. Полнота архива за
неделю или месяц не гарантируется.

`GET /environment/news` принимает `category`, `limit` от 1 до 20 и `cursor`;
возвращает `next_cursor` и `source_health`. Точные поля — в OpenAPI.
Контекст явных новостей и поиска ограничен 3200 символами, обычный фоновый
контекст — 1600.

## Пользовательский API и ключи

`web_search_provider`: `free` по умолчанию, необязательный `tavily`.
Исторические значения `brave` и `serper` читаются для совместимости,
но используют бесплатные резервы. Политика `web_search_free_only=true`
обязательна. Наличие ключа не переключает режим само по себе.

Перед Tavily-запросом `/usage` должен подтвердить допустимый бесплатный
профиль, пакет до 1000 кредитов и нулевые `paygo_usage/paygo_limit`.
Неясная квота, ошибка проверки, платный тариф или исчерпание блокируют API.
Локально атомарно резервируется расход в `search-budget.sqlite3`:
предел — 900 кредитов за календарный месяц UTC. Таймаут и отмена не возвращают
резерв; учитывается доступный внешний расход аккаунта.

Это защитная политика Iris, а не обещание условий поставщика. Перед
использованием ключа пользователь проверяет настройки своего аккаунта.

Ключи поиска независимы от ключей диалога и Coding Agent. Они хранятся в
Credential Manager и доставляются ядру через stdin; `.env` и окружение не
принимаются. Public settings показывает только признаки настроенных ключей.
Сохранение или удаление ключа перезапускает управляемое ядро, сохраняя режим.

`POST /environment/search/check` выполняется после пользовательского действия:
для Tavily проверяет тариф и один тестовый запрос с учётом квоты.
Brave/Serper отвечают `free_only` без сетевого обращения; без ключа —
`unconfigured`. Управление ключами в браузерном режиме отключено.

## Проверка

Основные офлайн-сценарии:

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_search_release_regressions.py tests/test_native_conversation_tools.py tests/test_search_free_autonomy.py tests/test_search_recovery.py tests/test_autonomous_web_search.py tests/test_awareness_retrieval.py tests/test_search_conversation_flow.py
```

Проверка живых бесплатных источников без LLM и ключей:

```powershell
.\.venv\Scripts\python.exe -m scripts.search_smoke_free
```

Офлайн-тесты проверяют логику, отмену, приватность и продолжение темы.
Доступность внешних сайтов проверяется отдельно; результат датируется.

# Поиск и новости Iris

По умолчанию Iris использует бесплатные источники без ключей. URL и служебные
команды не озвучиваются: источники, запрос и диагностика доступны в истории.

## Понимание запроса

Прямые просьбы «найди», «можешь поискать», «глянь в инете» и вопросы о текущих
версиях, новых героях, обновлениях и итогах выборов или соревнований запускают
проверку до генерации ответа. Разговорные формы названий («в дедлоке») приводятся
к названию сущности. Для вопроса о выборах в Госдуму без года используется
текущий местный год; явно названный год сохраняется. «Сейчас» уточняет последний
запрос, в том числе после короткого «алло».
Короткие уточнения используют последние восемь пользовательских реплик:
Deadlock → последний герой → «поищи выноти» даёт запрос о герое, а «вчера»
добавляет местный календарный период. Бессмысленный фрагмент сам по себе
поисковикам не отправляется. Приветствие, смена темы, личные данные и явный
запрет интернета прекращают продолжение предыдущего поиска.

Ясный запрос собирается правилами. Если явная просьба неоднозначна, выполняется
один структурированный вызов модели с контекстом до 2000 символов и таймаутом
две секунды. Результат — самостоятельный запрос или необходимость уточнения.
Расход планировщика включается в токены ответа. При ошибке или таймауте Iris
уточняет предмет, а не объявляет поиск недоступным.

Backend выдаёт «Так, секунду, проверю» при запуске проверки. Результат
возвращается в том же ходе. Пустая релевантная выдача, блокировка, таймаут,
ошибка и отсутствие вызова различаются; прошлый статус не доказывает состояние
инструмента сейчас. Знания модели, память разговора и веб-проверка различаются.
Ответ модели, состоящий только из «проверю» или «ща гляну», задерживается перед
озвучкой и исправляется один раз в том же ходе без повторного получения данных.
Если и исправление не даёт ответа, backend сообщает о конкретном результате
проверки. Стоимость исправления включается в статистику токенов.

## Источники и ограничения

Бесплатные провайдеры — DuckDuckGo HTML и Bing RSS. Для новостей и недавних
событий используется тематическая Google News RSS-выдача. При недостатке
результатов допускается одно переформулирование под предмет запроса, а не
универсальное добавление «официальный источник».

HTTP 200 не доказывает релевантность. Название сущности и существенная версия
проверяются отдельно от слов latest/hero/announcement. Учитываются русские
и английские варианты названий. Официальный домен повышает оценку только
после проверки темы. Слух не становится подтверждением от ранжирования.
Год выборов или соревнования обязателен для соответствия. Для вопроса о победителе
страницы с расписанием и подготовкой не прекращают поиск: проверяются оставшиеся
провайдеры в пределах лимита. В контексте и метаданных различаются информация
по теме и содержание с итогом; это диагностический признак, а не гарантия истинности.
Если найдены только предварительные результаты, поиск использует оставшийся
резерв для окончательных итогов; предварительные данные сохраняются с оговоркой.

Обычный поиск возвращает до трёх источников, новостной — до семи. Для свежих
событий, полного текста и другого варианта анекдота читаются до двух страниц.
Сниппет и прочитанная страница помечаются отдельно. Найденный вариант нельзя
объявлять единственным каноном. Без даты нельзя подтверждать конкретный день.

Подготовка запроса и получение данных имеют общий дедлайн десять секунд.
Бесплатный режим допускает до трёх поисковых обращений, выбранный API с
бесплатными резервами — до четырёх. Успешные результаты кэшируются пять минут,
ошибки — 30 секунд. Явный повтор обходит кэш результата, сохраняя минутный
cooldown после блокировки. Одинаковые запросы объединяются; отмена одного
ожидающего не отменяет поиск остальных.

Произвольная страница ограничена 512 КБ. Доступны публичные HTTP(S)-адреса
и стандартные порты; каждое перенаправление проверяется, TCP-соединение
закрепляется за проверенным IP. Внешний текст — данные, не инструкции.
Совместимы прежние JSON и live-команды web_search, включая необязательные
fallback_query и preferred_domains.

## Новости

17 RSS/Atom-лент покрывают general, tech, science, games. Игровые ленты:
DTF, IGN, Чемпионат и PC Gamer. Обновление после готовности чата запускается
в фоне; TTL источника — 15 минут, одновременно загружаются четыре ленты.
Каждый источник сохраняет состояние загрузки, число статей и дату обновления.
Выключение новостей прекращает новые фоновые загрузки.

Тематическая подборка ожидает загрузку до 2.2 секунды в пределах общего
дедлайна и при недостатке дополняется поиском. Статьи из RSS сохраняются.
Дайджест содержит до семи событий, API — до 20. События дедуплицируются,
общая подборка покрывает разные категории и источники. Статьи без даты не
включаются в свежую RSS-подборку; старше 48 часов требуют явного периода.
Кэш до двух часов допустим с пометкой stale.

«Ещё новости» восстанавливает тему, период и показанные события из метаданных
последнего ответа текущей сессии, включая после пересоздания агента. Другая
сессия или ответ по новой теме не продолжают подборку. При исчерпании доступных
событий Iris сообщает об этом. «Вчера» и «сегодня» рассчитываются по времени
Windows, а не по UTC. Архивная полнота за неделю/месяц не гарантируется.

GET /environment/news сохраняет прежние поля и принимает category, limit
(1..20, по умолчанию 8), cursor. Ответ содержит next_cursor и source_health.
Курсор сохраняет период и исключает ранее выданные события. Метаданные ответа
news и web_search сохраняются одновременно при тематическом дополнении.
Контекст обычного поиска ограничен 1600 символами, явных новостей — 3200.

## Собственный поисковый API

web_search_provider: free (по умолчанию), brave, tavily, serper. Наличие ключа
не включает API; режим выбирается пользователем в настройках внешних источников.
Используется только выбранный сервис. При его ошибке допустим бесплатный резерв,
но автоматического переключения на другой платный сервис нет.

Brave использует web/news search, Tavily — search с topic general/news и basic
search depth без автоматического повышения стоимости, Serper — search/news.
Ответы приводятся к общему формату и проходят локальное ранжирование.

Ключи независимы от DeepSeek и Coding Agent. Tauri сохраняет их в Windows
Credential Manager: brave_api_key, tavily_api_key, serper_api_key. Backend
получает их через существующий анонимный stdin-канал. Ключи не принимаются
из environment/.env, не входят в runtime settings, историю и сообщения ошибок.
Public settings содержит только search_api_keys_configured. Сохранение/удаление
ключа перезапускает управляемое ядро, сохраняя выбранный режим поиска.

POST /environment/search/check с provider отправляет один тестовый запрос
после явного действия пользователя и не меняет режим. Без ключа ответ
unconfigured, без обращения к сервису. Управление ключами доступно в
установленном приложении, в браузерном режиме оно отключено.

## Проверка

Офлайн-сценарии: tests/test_search_recovery.py, test_autonomous_web_search.py,
test_awareness_retrieval.py. Они проверяют разговорные уточнения, текстовый и
live-путь, резервные провайдеры, отмену, приватность, API-адаптеры и продолжение
новостей. Доступность бесплатных сайтов проверяется отдельно: они могут
менять разметку и ограничивать запросы. Проверки с платным API выполняются
с явно подключённым пользовательским ключом.

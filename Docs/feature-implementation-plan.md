# Развитие Iris: три этапа

Реализация утверждённого плана с поправками от 19 октября 2026 года.
Исходный план с пользовательскими пометками сохранён. Параллельные изменения
в рабочей копии не откатывались; коммиты и публикация не выполнялись.

Исключены F2 «Вернуться к теме», редизайн диалога и экрана состояния.
В истории убран общий переключатель; детали отдельных сообщений сохранены.
Переход к источнику добавлен для общего поиска. Вложение встроено в существующее
поле ввода, без перестройки сцены и панели диалога. F5 доступна только в DEV.

## 1. Интерфейс и обычные настройки

- [x] Обзор: исходный баннер с цветами, фактическая готовность и ближайшее напоминание. Подложки карточек совпадают с настройками.
- [x] История: убран общий переключатель детализации; раскрытие конкретной реплики осталось.
- [x] Память: отдельные карточки без общей нижней подложки, источник и дата, статистика в раскрытии, причина архива и замена.
- [x] Планы: создание через разговор с Iris, отдельные карточки с отступами, краткие состояния и раскрываемый перенос срока.
- [x] Coding Agent: одно действие в пустом состоянии, diff по файлам, количество изменений, раскрываемые фрагменты.
- [x] Настройки: профили участия с описаниями и полные параметры ниже; обычный темп голоса, устройства и управление оверлеем доступны без DEV.
- [x] Словари: редактируемые пары. Модели: назначение. Копии: дата, размер и состав. Расходы: отсутствие данных и расчётный характер суммы.
- [x] Система: готовность сценариев и подробности; обслуживание показывает объём данных; события группируют повторы.
- [x] Запуск: опциональный короткий финал после реальной готовности; новые UI-анимации используют Anime.js v4.
- [x] Инкогнито: видимый индикатор и пояснение фактической границы сохранения.

## 2. Первый запуск и напоминания

- [x] F6: мастер «ключ → модели → устройства → разговор» в «Настройки → Система → Обзор», сохранение шага, возможность подготовить голос позже, проверка наличия ключа.
- [x] Явная проверка уровня микрофона, пробная локальная фраза, остановка, отмена поздних ответов и освобождение ресурсов.
- [x] Недоступное выбранное устройство сохраняется и обозначается; обычное открытие мастера не запрашивает микрофон.
- [x] F1: зарегистрированный навык для текста и голосового пути, явная просьба и уточнение неоднозначного времени.
- [x] Сроки в SQLite, стабильный ключ создания, перенос, отмена и завершение; подтверждение доставки привязано к версии срока.
- [x] Карточка внутри Iris и интеграция Windows notification plugin с отдельным разрешением; пропущенные сроки ожидают доставки после запуска.
- [x] Без реального сохранения агент не подтверждает создание, включая голосовой поток и случай пропущенного вызова инструмента.

## 3. Документы, поиск и контекст памяти

- [x] F3: одно вложение TXT/MD/текстовый PDF, лимиты, чтение, отмена, удаление, проверяемые фрагменты D1 и страницы/строки.
- [x] Извлечение локальное; выбранные части отправляются внешней модели. Документ временный, источники ответа сохраняются в истории.
- [x] Ответы по документу не используются для автоматических личных фактов и при следующей фоновой консолидации.
- [x] F4: Ctrl+K, поиск по истории/памяти/планам/настройкам, точный переход, стрелки/Enter/Escape, защита от устаревших результатов.
- [x] F5: снимок реально переданных записей после отбора по бюджету; просмотр, исправление и одноразовое исключение только в DEV.
- [x] Пользовательское руководство, API, зависимости, конфиденциальность и условия выпуска обновлены.

## Что проверено

Проверки выполнялись на временных базах и в отдельном QA-профиле. Личные
история, память, ключи и процессы Iris для приёмки не использовались.

- Полный итоговый web-набор: **355 проверок прошли**, `--maxWorkers=2 --testTimeout=20000`.
- Итоговая серверная регрессия: **280 прошли** в 14 файлах, включая документы, напоминания, навыки, историю, контекст, память и голосовой API.
- Покрыты отсутствие вызова инструмента при ложном подтверждении, неоднозначное время, старое подтверждение перенесённого срока, отмена загрузки и фоновые окна памяти после документа.
- TypeScript и production web-build: успешно. Vite предупреждает о размере общего JS-фрагмента; сборка завершена.
- `cargo check` с notification plugin 2.3.3: успешно. Установщик не собирался.
- Браузер: обзор, мастер и его сохранённый шаг, отсутствие автоматического захвата, запрет старта без ключа, окна 1135×760 и 800×760, reduced motion.
- Браузер: точный переход из поиска и фокус; TXT загружен, D1 проверен и файл убран; напоминание доставлено внутри Iris, подтверждено и выполнено кнопкой.
- Проверка документации: успешно, 60 Markdown-файлов. Scoped `git diff --check`: успешно; исключённые файлы экрана состояния не менялись.

## Граница живой приёмки

Код трёх этапов реализован. Эти проверки ещё нужны именно для поставляемого
Windows-приложения и не заменяются браузером или автоматическими тестами:

- [ ] Реальные микрофон, выбранный аудиовыход и локальный TeraTTS; исчезновение устройства во время разговора.
- [ ] Уведомление Windows в трее, выход машины из сна, полный перезапуск и разрешения установленного приложения.
- [ ] Окончательный художественный просмотр с Unity-аватаром и масштабом Windows 125–150%.
- [ ] Живой диалог с внешней моделью; в QA личный API-ключ не использовался.

PDF без текстового слоя не поддерживается. Разбор большого документа частичный
(до восьми фрагментов); файл в RAM живёт до двух часов или перезапуска.
Напоминания требуют работающего Iris. Мгновенное прерывание уже начатого вызова
PDF-парсера не обещается. DEV-контекст показывает входные факты, а не внутренние
рассуждения; исключение записи не стирает ту же информацию из истории.

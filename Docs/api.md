# HTTP и WebSocket API

Точные поля запросов и ответов описаны в OpenAPI работающего ядра:
`/docs` и `/openapi.json`. Этот документ описывает авторизацию, группы маршрутов
и правила жизненного цикла, которые нужно сохранять при изменении клиентов.

## Адрес и авторизация

Браузерная разработка по умолчанию использует `http://127.0.0.1:8000`.
При управляемом запуске Tauri выбирает случайный локальный порт и временный
токен сессии.

Требование токена включается при заданном desktop-токене. При раздельном
запуске разработки без него локальные HTTP/WS-запросы не требуют авторизации;
этот режим нельзя выставлять в сеть. OpenAPI управляемого ядра тоже защищён.

| Транспорт | Передача токена | Ошибка авторизации |
| :--- | :--- | :--- |
| HTTP | Заголовок `X-NeuroAsist-Token` | `401` |
| WebSocket | Параметр запроса `token` | Соединение закрывается |

Токен нельзя сохранять в настройках, отчётах или журналах URL. CORS допускает
настроенные локальные источники. Номера протоколов независимы от версии продукта.

## HTTP

| Маршруты | Назначение |
| :--- | :--- |
| `/health`, `/readiness`, `/status` | Доступность ядра, готовность подсистем и версия |
| `/chat`, `/chat/live` | Текстовый ответ и общая оркестрация потокового диалога |
| `/conversation/*` | Активная сессия, состояние персонажа, рефлексии и диагностика |
| `/timeline/*`, `/episodes/*` | Сообщения, журнал, поиск и жизненный цикл эпизодов |
| `/memory/*` | Память, темы, обязательства, аудит и поисковый индекс |
| `/environment/status`, `/environment/news`, `/environment/search/check` | Состояние источников, подборки новостей и проверка поискового API |
| `/settings/*`, `/models/*` | Несекретные настройки, словари и управление моделями |
| `/voice/*`, `/avatar/*` | Прерывание, озвучка, команды и состояние аватара |
| `/coding/*` | Задания, просмотр и применение изменений Coding Agent |
| `/events`, `/diagnostics`, `/backups` | События, обслуживание и резервные копии |
| `/debug/llm/usage` | Токены, кэш, попытки и задержки без содержимого диалога |

`/voice/chat` не поддерживается и возвращает `404`. Голосовой ввод поступает
через WebSocket v3, ответ использует общий путь диалога. У резервных копий
реализованы создание, список и удаление; маршрут восстановления отсутствует.

## WebSocket

Повтор текстового запроса использует прежний `client_message_id`. `/chat/live`
возвращает `replayed`, исходные идентификаторы, `assistant_message_id`, `status`
и сохранённый `reply`; завершённый ответ не запускает генерацию и аудио заново.
Для `/chat` повтор ещё выполняющегося запроса возвращает `409`, готового —
сохранённый ответ и его статус.

Список `/memory` принимает `status=active` или `status=archive`, `q`, `limit`
и `offset`. Фильтры применяются до ограничения; `next_offset` указывает следующую
страницу или равен `null`. Прежние поля списка сохранены.

### События · `/ws/events`

Передаёт события исполнения для интерфейса: идентификатор, тип, уровень,
сообщение и метаданные. Полные запросы модели и скрытые рассуждения не являются
частью этого контракта. `retrieval.progress` сообщает этап поисковой операции;
отмена и завершение привязаны к конкретному ходу.

### Микрофон · `/ws/voice-input/{session_id}?version=3`

Клиент отправляет `voice.input.start`, непрерывные бинарные PCM16-фреймы и
`voice.input.stop`. Поля начала потока и поведение при остановке описаны в
[живом разговоре](live-conversation.md#websocket-v3).

Версии 1/2 и прежнее поле `mode` отклоняются. Переподключение создаёт нового
владельца соединения и отменяет задачи прежнего. Обычный `stop` дожидается
подтверждённых задач ввода; разрыв соединения инвалидирует их владение.

### Ответ · `/ws/voice/{session_id}?version=1`

Канал аудио и управления ответом. Его версия намеренно отличается от входного
протокола. Не повышайте её при изменении версии приложения или микрофонного канала.

### Аватар · `/ws/avatar?version=2`

Unity регистрирует поддерживаемые версии, получает команды речи, эмоций,
жестов и размещения, подтверждает воспроизведение. Несовместимая версия
закрывается с ошибкой политики. Схемы находятся в
[`app/avatar`](../apps/backend/app/avatar/) и [`apps/protocol`](../apps/protocol/).
Транспорт пока принимает `version=1` и `version=2` (при отсутствии параметра —
`1`); штатный Unity-клиент использует `2`. Поле `protocol_version` в Avatar
envelope также принимает `1` или `2`. Character Protocol v3 — отдельная схема
ответа персонажа, она не повышает версию Avatar-транспорта.

## Подготовка локального приложения

`GET /models` и `/readiness` показывают установленные модели и состояния
`downloading`, `verifying`, `cancelled`, `failed`. `POST /models/{id}/install`
запускает проверяемую загрузку, `POST /models/{id}/cancel` запрашивает отмену.
Карточки моделей содержат необязательные `delivery`, `source_url`, `terms_url`
и `license`. Для `upstream_download` файлы загружаются напрямую из закреплённого
snapshot Hugging Face; отсутствие SPDX-лицензии передаётся как `null`.
Удаление модели в управляемом desktop выполняется native-командой
`remove_managed_model` после остановки ядра, а не во время инференса.

`POST /coding/projects` регистрирует явно выбранную папку. `GET /coding/image`,
`POST /coding/image/prepare` и `/coding/image/cancel` управляют подготовкой
поставляемого Docker-контекста. Эти HTTP-запросы требуют авторизацию ядра.

Список, создание и удаление копий остаются HTTP-операциями. Native-команды
`import_backup` / `export_backup` открывают системный диалог, а `restore_backup`
останавливает ядро, выполняет maintenance и запускает его снова. Работающая база
не заменяется HTTP-запросом. Ключи и старые активные Coding-задания не переносятся.

## Напоминания, документы и контекст

Все маршруты используют существующую авторизацию локального ядра.

| Маршрут | Назначение |
| :--- | :--- |
| `GET /reminders?due_only=true` | Ожидающие доставки сроки; без фильтра — список напоминаний |
| `POST /reminders` | `title`, будущий `due_at` ISO 8601 с поясом, необязательный `timezone_label` |
| `PATCH /reminders/{id}` | Новый срок и/или `status`: `open`, `completed`, `cancelled` |
| `POST /reminders/{id}/ack` | Подтверждение показа для точного `delivery_token`; старый токен не подтверждает перенесённый срок |
| `POST /voice/preview` | Фиксированная локальная TTS-проба; аудио удаляется после передачи |
| `POST /documents` | Multipart: активный `session_id`, уникальный `upload_id`, один `file` |
| `GET /documents/current?session_id=...` | Текущее вложение, число фрагментов и оставшееся время жизни |
| `DELETE /documents/{id}?session_id=...` | Удаление или отмена ещё обрабатываемой загрузки |
| `GET /documents/{id}/sources/{D1}?session_id=...` | Проверяемый извлечённый фрагмент своей беседы |
| `GET /timeline/messages/{id}/context` | Ограниченное окружение точного сообщения, эпизод/сессия и смещение для продолжения чтения |
| `GET /memory-context/{assistant_message_id}` | Только DEV: снимки реально переданных записей памяти и их текущее значение |
| `POST /memory-context/exclude-next` | Только DEV: `session_id`, `memory_id`; одноразовое исключение записи из следующего контекста |
| `GET /maintenance/preview` | Количество сообщений, эпизодов, фактов, архивных записей и планов без их содержимого |

Срок остаётся в SQLite до изменения пользователем; подтверждение доставки не
равно выполнению плана. Доставка требует работающего UI. Уведомление Windows
использует Tauri notification plugin и отдельное разрешение пользователя.
Навык `create_reminder` возвращает `due_at` в UTC и `display_due_at` с сохранённым
смещением для подтверждения пользователю. Повтор того же исходного запроса
возвращает прежний срок; отменённый или выполненный запрос не создаёт запись
заново. Изменение срока или состояния меняет `delivery_token`.

Документы ограничены 10 МБ, 150 000 символами и 100 страницами PDF. В RAM
хранится одно вложение на беседу, не более 16 бесед, до двух часов. Оригиналы
не сохраняются. Извлечение проверяет отмену между страницами/фрагментами;
уже начатый вызов PDF-парсера не является мгновенно прерываемым процессом.
Модель получает до восьми фрагментов с ID и признаком `partial`; снимок
источников сохраняется в `metadata.document_context` ответа без поля `text`:
название файла, `id`/`label` источников, `partial`, `source_text_persisted=false`.
Исходный текст передаётся модели только в эфемерном prompt. Прежние metadata
с полем `text` автоматически не переписываются. Автоматическое
извлечение памяти исключает такие ответы и в последующих заданиях.

`metadata.context_memories` содержит снимок входного контекста после отбора
и ограничения бюджета. Обычные списки, поиск и окружение сообщений не
возвращают это поле вне DEV. Снимок не доказывает влияние каждого факта на
формулировку; исключение записи не удаляет тот же факт из истории разговора.

## Совместимость

- Клиент сверяется со схемой, а не угадывает поля по примерам.
- Неизвестная версия протокола отклоняется явно.
- `session_id`, `generation`, `turn_id` и `utterance_id` задают принадлежность
  результата; позднее событие старого поколения игнорируется.
- Там, где восстановление требует такого порядка, данные сохраняются до
  публикации зависящих от них событий.
- Изменение номера продукта не меняет миграции SQLite и версии транспорта.

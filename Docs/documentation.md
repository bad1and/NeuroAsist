# Поддержка документации

Документы помогают запустить приложение, понять поведение и проверить сборку.
Главная карта — [`index.md`](index.md). Каждое описание относится к коду или
конкретному датированному измерению; будущие возможности обозначаются отдельно.

## Структура

| Место | Содержание |
| :--- | :--- |
| `Docs/index.md` | Вход по задачам читателя |
| `Docs/user-guide.md` | Пользовательское поведение без внутренней реализации |
| `Docs/` | Действующие описания подсистем и выпуска |
| `Docs/archive/` | Исторические планы; не инструкции текущего продукта |
| Корневые политики | Участие, безопасность, конфиденциальность и ассеты |
| README подсистем | Локальная установка и справочные сведения |

Главный `README.md` знакомит с приложением на русском и ведёт к `Docs/index.md`.
`README.en.md` содержит английскую редакцию с той же структурой, изображениями
и переведёнными подписями. `README.ru.md` оставлен как короткий переход для
прежних ссылок. Переключатель языка ведёт напрямую между двумя редакциями.

## Что изменено в русской редакции

Обновлены действующие документы архитектуры, API, голоса, памяти, поиска,
Coding Agent, окружения, эксплуатации и выпуска. Добавлены руководство
пользователя и шаблон карточки сборки. Корневые политики приведены к тому же
языку и проверены на противоречия с реализацией.

Удалён `deferred-release-work.md`: заметка дублировала текущие условия выпуска,
внутренних ссылок на неё не было. Прежний milestone голоса сокращён до
исторического указателя; полный контракт находится в `live-conversation.md`.

Архивные планы сохранены: на них ссылается неизменённый `Docs/archive/README.md`.
Исторический манифест версии не переписывается.
При следующем пересмотре README можно отдельно убрать ненужные архивные файлы
вместе с их ссылками, сохранив историю в Git.
Qwen обозначен как эксперимент, измерения STT сохраняют дату и условия.

## Оформление

- В Markdown используйте небольшой знак Iris и короткий путь обратно к
  документации. В общем предпросмотре логотип остаётся только в меню;
  повторная шапка каждой страницы скрывается. Wordmark — на странице входа.
- Называйте документы прямо: «Архитектура», «Память», «Порядок выпуска».
  Начинайте с назначения и условий,
  затем давайте действия, схему или таблицу.
- Не добавляйте наборы рекламных значков, украшения и повторяющиеся обещания.
- Сохраняйте относительные ссылки, чтобы документ работал в GitHub и клоне.
- Таблицы используйте для сравнения и маршрутов, списки — для действий.
- Не переводите имена API, полей, файлов, моделей и команд.
- Команды PowerShell выполняются из корня; заменяемые значения поясняются рядом.

## Проверка содержания

При изменении поведения обновите документ подсистемы, связанные политики,
условия выпуска и пользовательские примечания. Не переносите старые
результаты тестов на новую сборку.

Проверяйте путь секрета, место хранения, порядок отмены и сохранения, настройки
по умолчанию и фактический состав сборки по исходникам. Перечисляйте ограничения
там, где читатель принимает решение.

```powershell
.\.venv\Scripts\python.exe scripts/check_docs.py
.\.venv\Scripts\python.exe -m pytest -q tests/test_check_docs.py
```

Автоматическая проверка покрывает метаданные версии, параметры `.env.example`,
профили зависимостей, локальные ссылки, якоря Markdown и HTML-изображения,
языковые переходы и совпадение локальных изображений в двух README.
Она не подтверждает доступность внешних сайтов, корректность юридической
интерпретации или испытания установщика.

## Языковые редакции

Сначала проверяется русский текст, затем готовится английская редакция
с теми же командами, оговорками и структурой. Перевод не меняет смысл статусов
и не удаляет ограничения. Главный README доступен на обоих языках;
профильные документы в `Docs/` пока ведутся на русском.

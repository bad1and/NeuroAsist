# Iris: готовность к финальной сборке перед установщиком

Дата: 20 октября 2026 года. Это аудит и план завершения существующего продукта.
Исправления исходников, сборка установщика, коммиты и публикация не выполнялись.

**Переходить к финальному кандидату пока рано:** найдены воспроизводимые ошибки
в выборе Coding-задачи, сроках напоминаний и хранении документов, дефекты путей
отказа desktop и пробелы сборочных проверок. После исправлений нужны свежая
сборка каталога приложения и приёмка именно этого каталога. Установщик — следующий этап.

  Включены незакоммиченные документы, напоминания, мастер, поиск и изменения Unity.

  Это не построчное ревью всех сторонних Unity/VRM-пакетов и бинарных ассетов.

## 3. Обязательные исправления перед кандидатом

P1 здесь означает необходимость закрыть пункт до фиксации финального каталога
приложения. P2 — завершение заявленных сценариев и документации до его приёмки.
Сопоставление с advisory отдельно от доказательства эксплуатации приложения.

### A1 · P1 · Coding Agent может применить другую задачу

`apps/web/src/coding.tsx:191` вызывает `getCodingTask(selectedId).then(setSelected)`
без проверки актуальности выбора. Apply на строке 410 использует `selected.id`.
Поздняя ошибка также может сбросить более новый просмотр.

**Воспроизведено:** A → назад → B → поздний ответ A → Apply. Настоящий компонент
в jsdom показал сначала `Task B`, затем `Task A`; apply получил ID `A`.
Реальные файлы не применялись, API заменены изолированными ответами.

**Завершить:** отменять/игнорировать старые запросы, связывать загруженные данные
с актуальным selectedId; запрещать Apply/Cancel/Retry при несовпадении ID.
**Приёмка:** поздние успех и ошибка A не меняют B и не допускают действие над A.
Доказательство: `web-repro.cjs`, `web-repro.json` в каталоге логов.

### A2 · P1 · Исходный текст документа сохраняется шире обещанного

`apps/backend/app/documents.py:188` включает текст выбранных источников в metadata.
`app/api/routes/chat.py:318`, `apps/backend/main.py:484` и
`app/agents/character/agent.py:2426` сохраняют document_context в SQLite.
Это до восьми фрагментов по 1600 символов, включая текст, которого нет в ответе.
Такая SQLite входит в ZIP. Удаление вложения очищает RAM, но не эти метаданные.

`PRIVACY.md:35` обещает RAM до двух часов/перезапуска и отдельно сохранение
фрагментов уже полученных ответов. Текущий договор хранения недостаточно точен.

**Воспроизведено:** маркер отсутствует в видимом ответе, но остаётся в metadata
после удаления вложения и повторного открытия SQLite.

**Завершить:** выбрать и реализовать договор хранения. Предпочтительный вариант —
не сохранять скрытый исходный текст; для исторических источников отдельно определить
согласованное хранение, удаление и понятное описание. Учесть уже записанные фрагменты
и резервные копии без молчаливого удаления пользовательской истории.
**Приёмка:** SQLite/ZIP после удаления соответствуют объявленной политике;
проверены обычный чат, streaming/live и голосовые метаданные.
Доказательство: `backend-repro.py`, `backend-repro.txt`.

### A3 · P1 · Напоминания подтверждают неправильную дату

`apps/backend/app/reminders.py:220–250` повторно вычисляет срок по ограниченному
разбору фразы, заменяя даже правильный tool timestamp значением «сегодня».
При фиксированных 20 октября, 11:00 МСК воспроизведено:

| Запрос | Правильный аргумент инструмента | Фактически сохранено |
| :--- | :--- | :--- |
| «Напомни 23-го в 19:00» | 23 октября, 19:00 | 20 октября, 19:00 |
| `Remind me tomorrow at 19:00` | 21 октября, 19:00 | 20 октября, 19:00 |
| «Завтра в двенадцать ночи» | Полночь | 21 октября, 12:00 |

Во всех случаях результат — `scheduled`. «Через пять минут» дополнительно
отклоняется как `needs_time`, хотя срок однозначен.

**Завершить:** не подменять корректную дату частично распознанной фразой;
при неоднозначности уточнять; подтверждать фактически сохранённые дату и время.
**Приёмка:** RU/EN, числительные, число месяца, полночь, относительное время,
переход суток/месяца, timezone, перенос, старый ACK, повтор запроса и перезапуск.
Доказательство: `backend-repro.py`, `backend-repro.txt`.

### A4 · P1 · Ранний отказ ядра может оставить бесконечный запуск

`apps/desktop/src-tauri/src/main.rs:255` выставляет `starting`, но ошибки создания
профиля, Credential Manager, отсутствующего EXE и spawn возвращаются через `?`
без публикации `failed`. Фоновый запуск на строке 1523 отбрасывает Result.
`StartupScreen.tsx:315` показывает повтор/восстановление для failed/crashed.

**Подтверждение:** статически прослежен путь отказа; fault injection desktop не выполнялась.
**Завершить:** единый переход в failed с понятной диагностикой для всех ранних ошибок.
**Приёмка:** отсутствующий EXE, отказ доступа и ошибка хранилища ключей дают
ограниченное ожидание, причину и рабочий повтор/восстановление.

### A5 · P1 · Safe Mode содержит гонку single-instance

`main.rs:1676` запускает второй EXE с `--safe-mode` до выхода первого.
Callback single-instance на строке 1446 игнорирует аргументы. Пока первый
процесс удерживает mutex, плагин перенаправляет запуск в него и завершает второй.
После выхода первого Iris может оказаться полностью закрытой.

**Подтверждение:** код приложения и локальный исходник плагина 2.4.3;
это статически подтверждённая гонка, живое воспроизведение ещё нужно.
**Завершить:** надёжная передача режима/перезапуск после освобождения экземпляра.
**Приёмка:** повторять переход при загруженном ядре; остаётся один Iris с
safe_mode=true, без Unity/preload и оставшихся дочерних процессов.

### A6 · P1 · Packaged smoke допускает аварийный exit

`scripts/smoke_packaged_runtime.ps1:73–79` дожидается остановки и печатает ExitCode,
но не отклоняет ненулевое значение. Shutdown с последующим падением может дать
формально успешный сборочный шаг.

**Завершить:** требовать ExitCode=0 и сохранять диагностический результат;
аналогично усилить managed smoke, который также не проверяет код явно.
**Приёмка:** контрольный процесс с ненулевым exit после shutdown проваливает smoke;
настоящий кандидат завершает процесс с 0. Это дефект проверки, не доказательство
того, что нынешнее ядро действительно падает.

### A7 · P1 · Зависимости требуют отдельного security-разбора

OSV-сопоставление выполнено по точным pins `requirements/constraints.txt` и всем
registry-записям Cargo.lock. Совпадения: 15 Python и 11 Rust версий пакетов.
В Rust присутствуют также Linux/macOS-зависимости и уведомления о прекращении
сопровождения. 115 ID не равны 115 независимым уязвимостям Iris.

Особенно важен закреплённый `starlette==0.46.2`: upstream подтверждает
[блокировку event loop при multipart-загрузке](https://github.com/Kludex/starlette/security/advisories/GHSA-2c2j-9gv5-cj73)
и [DoS в разборе Range у FileResponse](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8).
В Iris используются UploadFile для документов/аудио и FileResponse для аудио.
Управляемое ядро ограничено loopback и токеном, поэтому внешний неавторизованный
доступ не доказан. Совпадение версии и используемых API требует исправления/разбора.

Текущий FastAPI 0.116.0 требует `starlette<0.47.0,>=0.40.0`: обновление только
Starlette вне диапазона разрушит согласованность. Обновлять совместимую пару
и её ограничения, затем повторять regressions, upload/streaming/Range и packaging.

Для ONNX, transformers, sentence-transformers, torch, chromadb и транзитивных
пакетов отдельно определить достижимость опасных API, доверие к весам и платформу.
Не переносить серверные RBAC-сценарии Chroma на embedded SQLite без доказательства.
**Приёмка:** для каждого актуального advisory — исправление либо обоснованная
неприменимость к фактическому артефакту; проверка повторена на его составе.
Данные и скрипт: `osv-lock-scan.json`, `osv-lock-scan.py`; [метод API OSV](https://google.github.io/osv.dev/post-v1-querybatch/).

### A8 · P2 · Английский интерфейс оставляет окна русскими

`apps/web/src/i18n.ts:1109,1132` переводит/наблюдает только #root;
`AppDialog.tsx:214` и token popover выводятся в document.body.
Воспроизведено настоящим locale hook: root=`Settings`, portal=
`Подготовить первый разговор`, lang=`en`.

**Завершить:** охватить портальные поверхности переводом без изменения текстов
пользователя и документов. **Приёмка:** мастер, Ctrl+K, подтверждения удаления/
восстановления, источники и токены; RU→EN при открытом окне и EN→RU.
Тест должен создавать настоящий #root и настоящий портал.

### A9 · P2 · Поиск и сортировка памяти частично не действуют

`memory.tsx:342,349` не передаёт searchQuery при запросе тем/планов, хотя API
поддерживает q. `RemindersPanel.tsx:52` заново сортирует планы по сроку, отменяя
выбранную родителем сортировку. Пользователь видит элементы управления без эффекта.

**Приёмка:** два различимых элемента, запрос, очистка, все видимые сортировки;
либо скрыты действительно неподдерживаемые действия. Не путать с Ctrl+K:
это отдельный локальный фильтр внутри раздела памяти.

## 5. Существующие бинарные файлы и лицензии

Последний найденный полный кандидат `output/v1-preinstaller/candidate-persona-20261012`
имеет манифест 12 октября, commit `7d15ca2c`, source_dirty=true, 7706 файлов,
distribution_approved=false. Записанные source hashes backend/Web/Rust/Unity
отличаются от текущих. Его нельзя назвать финальным кандидатом нынешнего дерева.

Release-окружение не содержит pypdf, хотя runtime/constraints уже требуют 6.21.1.
Обычный импорт PdfReader доступен статическому анализу PyInstaller; отсутствие
пакета в старой среде не доказывает необходимость hidden-import.
Финальную сборку делать со свежими зависимостями и ядром; PDF проверить в ней.
`-ReuseCore` проверяет существование EXE без соответствия исходникам,
`-SkipAvatarBuild` также не доказывает свежесть Unity.

Перед распространением оформить по фактическому составу:

- Разрешение на VRM именно для Iris и отдельно допустимость публикации исходного
  VRM. Владелец ранее подтвердил наличие разрешения; его текст здесь не проверен.
- Mixamo, шрифт Proxima Nova, веса STT/TTS/VAD/Smart Turn и включённый код.
- UniVRM/Unity, PyAV/FFmpeg, Python/npm/Rust и системные компоненты.
- Требуемые notices/credits и основание разрешения по каждому компоненту.

Это открытая доказательная работа из `THIRD_PARTY_ASSETS.md`, а не заключение
о неправомерности использования и не просьба повторно подтверждать уже данное разрешение.
Автоматический inventory перечисляет лицензии, но не одобряет распространение.

Для этапа NSIS найден отдельный пробел: `scripts/build-desktop-release.ps1:180–197`
копирует LICENSE, PRIVACY, THIRD_PARTY_ASSETS, licenses и THIRD_PARTY_NOTICES только
в AppOnly. Их наличие в каталоге приложения не обеспечивает наличие в NSIS.
Включить notices в фактический установщик и проверить после установки.

## 7. Матрица живой приёмки перед установщиком

| Сценарий | Обязательная проверка | Что считать успехом |
| :--- | :--- | :--- |
| Новый профиль | Нет ключей/весов; мастер; текст до голоса; явный микрофон | Понятные состояния и восстановление шага; нет скрытого захвата |
| Модели | Скачать, отменить, повторить; offline, повреждение, мало диска | Частичная модель не объявляется установленной; текст остаётся доступен |
| Диалог | Поток, отмена, reconnect, ошибки ключа/лимита/API | Нет дублей, старых ответов и бесконечного spinner |
| Память/персонаж | Факт, короткий ответ, исправление, удаление, инкогнито, перезапуск | Корректный контекст без возврата удалённых фактов; версия проверочного корпуса записана |
| Стоимость | 30 минут живого диалога и фоновых заданий | Заранее заданный бюджет, retries <2%, учтены все служебные вызовы |
| Поиск | Найдено/пусто/ошибка/кэш, источники, запрет интернета, отмена | История соответствует реальным операциям; нет выдуманного подтверждения |
| Голос | Час, реальные устройства, шум, перебивания, исчезновение/возврат устройств | Нет старых реплик и остановки workers; P50/P95 реального звука измерены, целевой warm P95 ≤2,5 с |
| Unity | Desktop и in-app; масштаб Windows 125–200%, движение/липсинк | Естественные безопасные движения, правильные границы, нет процессов после выхода |
| Напоминания | RU/EN, перенос/отмена, сон/перезапуск, трей/permissions | Правильный срок; нет старого уведомления и повторной доставки |
| Документ | TXT/MD/PDF, D1, отмена/удаление/истечение, скан без текста | Источники проверяемы; хранение отвечает A2; документ не становится личным фактом |
| История/память/поиск | Точный переход, локальные фильтры, длинные списки | Верная запись и фокус; пагинация и сортировки не теряют элементы |
| Копии | Старый/новый ZIP, повреждение, миграция, прерывание restore | История/память/планы/словарь/настройки восстановлены; rollback сохраняет прежние данные |
| Coding Agent | Нет Docker, подготовка/отмена/повтор, review/apply, конфликт, аварийный restart | Выбрана верная задача; исходники не теряются; сеть/хост недоступны sandbox |
| Desktop lifecycle | Второй экземпляр, трей, close/quit, crash, retry, safe mode | Один экземпляр; явные ошибки; корректный shutdown и отсутствие orphan processes |
| RU/EN и доступность | Диалоги/порталы, клавиатура, focus restore, 800×760, DPI, reduced motion | Все действия доступны, текст читаем, переводы полны |
| Среда без dev tools | Read-only каталог приложения, иной cwd и чистый Windows-профиль | Все изменяемые файлы в пользовательском профиле; Python/Node/Rust не требуются |

Часовой synthetic soak и unit tests не закрывают настоящий микрофон, Unity,
Windows notification permissions или восстановление через настоящее окно.
Для каждого сценария нужны ожидаемый результат, фактический результат, среда,
длительность и ссылка на обезличенное подтверждение.

## 8. Что можно отложить

Разбиение большого App.tsx/CSS, дальнейшее уменьшение JS bundle, новые функции,
дополнительные жесты и общий редизайн. Размер JS сейчас даёт предупреждение,
но сам по себе не является доказанным препятствием выпуску. Новые функции
расширили бы матрицу приёмки; полезнее завершить и проверить существующие.

Следующее завершённое состояние проекта: исправленные перечисленные дефекты,
актуальные документы, зафиксированный commit и новый принятый каталог приложения.
После него можно выполнять отдельный этап установщика и публикации.

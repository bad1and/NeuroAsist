# Milestone 7 — Character Protocol v3

The canonical contract is `apps/protocol/character-turn.schema.json`. It owns
the visible reply plus non-visible affect, gesture, delivery and continuity
metadata. Python is the source model; checked-in TypeScript and C# DTOs are
generated by `scripts/generate_character_protocol.py`.

## Compatibility

- Character model v1/v2 flat fields (`emotion`, `gesture`, `intent`) are
  accepted by the adapter and converted to `CharacterTurn`.
- Existing REST, TTS and Avatar v1/v2 callers still receive their flat fields.
- Live voice emits its avatar directive in a separate `voice.metadata` frame;
  that frame is never appended to a visible reply or TTS text.
- Invalid v3 metadata retains a valid `reply`, uses deterministic local cues,
  and produces a diagnostic event.

## Regeneration and parity

```powershell
.\.venv\Scripts\python.exe scripts/generate_character_protocol.py
.\.venv\Scripts\python.exe -m pytest tests/test_character_protocol_v3.py
```

`test_character_protocol_v3.py` compares the canonical enum values with the
generated JSON Schema, TypeScript and C# artifacts. A future Unity source tree
can copy the generated C# DTO without changing the wire contract.

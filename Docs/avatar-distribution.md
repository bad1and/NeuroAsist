# Раздельная сборка Iris и закрытого аватара

Решение от 24 октября 2026 года: `bad1and/NeuroAsist` остаётся публичным.
Закрыто собирается **только Unity**. Публичная сборка получает готовый Player
и собирает приложение; установщик и публикация EXE добавляются позднее.

## Репозитории и границы

| Место | Содержимое |
| :--- | :--- |
| [bad1and/NeuroAsist](https://github.com/bad1and/NeuroAsist) | Код приложения и Unity, сцена с сохранёнными GUID, инструменты импорта и проверки, открытый workflow сборки приложения |
| `Gogowski/NeuroAsist-avatar-private` (private) | VRM, ограниченные анимации и производные данные, `assets-manifest.json`, workflow Unity |
| Между сборками | Только `iris-avatar-windows.zip`: готовый Player и манифест файлов |
| У пользователя | В будущем один EXE-установщик из публичного GitHub Releases |

Закрытый репозиторий создан в аккаунте владельца `Gogowski`; для `bad1and`
отправлено приглашение с правом записи. Нынешний публичный репозиторий
не переименовывается и не переводится в private. Новая рабочая ветка — `v0.9.1`;
имя ветки не меняет версию продукта `1.0.0`.

## Как работает сборка

1. В закрытом репозитории вручную запускается `Build private Iris Unity Player`
   с **полным SHA проверенного публичного commit**. Код берётся из публичного
   репозитория, а материалы — из закрытого. Две копии кода не сопровождаются.
2. Публичные исходники проверяются на отсутствие модели. До импорта записываются
   SHA commit и digest входных файлов Unity, протокола и инструмента поставки.
3. `avatar_assets.py import-private` проверяет все хеши входных материалов
   до копирования. Существующие файлы проекта не перезаписываются.
4. Unity 2022.3.62f3 собирает Windows Player. Пакет содержит только EXE, DLL,
   штатные ресурсы Unity и манифест. VRM, FBX, Unity Library/Temp, сцена и
   самостоятельные исходные ассеты не допускаются.
5. Публичный `Build Windows application candidate` получает полный SHA кода
   приложения, точный приватный run ID и независимо проверенный SHA-256 архива.
   Он проверяет архив, каждый
   файл, версию Iris и digest исходников Unity в текущем checkout.
6. Сборка приложения идёт в режиме `AppOnly`: каталог с Iris.exe, ядром,
   аватаром, notices и манифестами. NSIS и публикация Release не запускаются.

Digest Unity позволяет после сборки компонента добавлять документацию и
прикладные изменения, сохраняя совместимость Player. Изменение исходников
Unity или протокола требует новой сборки компонента. Хеш архива должен быть
получен из доверенного результата закрытой сборки; хеш из самого скачанного
архива не является независимой проверкой.

## Доступы GitHub Actions

- Unity runner: только закрытый репозиторий, метки `self-hosted`, `Windows`,
  `iris-avatar-private`; установленный и лицензированный Unity Editor.
- Workflow Unity запускается вручную и только в private repository.
  Публичные PR на этом runner не исполняются.
- Для скачивания artifact публичной сборке нужен отдельный fine-grained token
  `IRIS_AVATAR_ARTIFACT_READ_TOKEN`: доступ только к закрытому репозиторию,
  разрешение **Actions: read**. Обычный GITHUB_TOKEN публичного репозитория
  не предоставляет такой доступ автоматически.
- Не использовать личный токен с широкими правами как секрет публичной сборки.
  Токен хранится в GitHub Secrets; доступ к release-сборке следует ограничить
  проверенными разработчиками и защищённым environment `release-candidate`.
- Точка ручного запуска workflow должна находиться в default branch GitHub.
  В старом `main` сохраняется только такой вход; сам код приложения workflow
  получает по переданному полному SHA, например из `v0.9.1`.
- Новый artifact имеет срок хранения 30 дней. Для будущего релиза нужно отдельно
  закрепить долговременный компонент; истёкший Actions artifact не считать
  архивом выпуска.

Шаблон закрытого workflow открыт в
[`build-support/avatar-private/build-unity.yml`](../build-support/avatar-private/build-unity.yml).

## Локальные команды

В новом чистом checkout публичных исходников:

```powershell
python scripts/avatar_assets.py check-public
python scripts/avatar_assets.py record-source --output build/avatar-source.json
python scripts/avatar_assets.py import-private --private D:\path\NeuroAsist-avatar-private
$env:NEUROASIST_UNITY_EDITOR = 'D:\unt\2022.3.62f3\Editor\Unity.exe'
.\apps\avatar-unity\scripts\build-windows.ps1
python scripts/avatar_assets.py package-player `
  --player apps/avatar-unity/Builds/NeuroAsistAvatar `
  --source-record build/avatar-source.json --archive build/iris-avatar-windows.zip
```

Публичная сборка приложения, получившая проверенный архив:

```powershell
.\scripts\build-preinstaller-app.ps1 -RequireCleanWorktree `
  -AvatarPackage D:\delivery\iris-avatar-windows.zip `
  -AvatarPackageSha256 '<SHA-256 из доверенной закрытой сборки>' `
  -ArtifactDirectory artifacts\candidate
```

Для локальных команд необходимы окружение проекта и зависимости сборки.
Импорт частных материалов выполняется в отдельном checkout. Старая рабочая
папка с уже существующими ресурсами остаётся пригодной для разработки;
её файлы инструмент импорта не заменяет.

`build-desktop-release.ps1` формирует resource mapping Tauri отдельным override.
Обычный `tauri build` сам по себе не добавляет Player в production bundle.
При передаче пакета сохраняется `avatar-component.json`: версия, исходный
commit, digest Unity, хеш архива и полный перечень файлов.

## Очистка прежней истории

24 октября очистка обычных веток применена. В свежем clone исключённые
ресурсы отсутствуют во всей доступной истории веток. Старые PR refs GitHub
всё ещё требуют отдельного решения владельца и GitHub Support.
[Результат и инструкция второму разработчику](avatar-distribution-result-2026-10-24.md).

Одновременно сохранить старые SHA всех commits и удалить из них VRM невозможно.
Выбран согласованный переход: отдельный mirror, резервная копия, фильтрация,
проверка сохранности остальных файлов и затем обновление существующих refs.
Адрес, публичность, issues и stars репозитория сохраняются.

[`prepare_avatar_history.py`](../scripts/prepare_avatar_history.py) не имеет
операций push. Он требует отдельный bare mirror, сохраняет Git bundle,
old/new mapping и удаляет частные данные по blob ID и известным каталогам.
Это охватывает переименованные копии модели. Глобальные фильтры `*.vrm` и
`*.gltf` не используются: они могут удалить каталоги кода `com.vrmc.vrm`
и `com.vrmc.gltf`. После фильтрации сверяются mode/type/blob всех остальных
файлов на вершинах веток и PR refs.

Локальные незакоммиченные изменения сохраняются отдельно. Они не включаются
автоматически в коммит инфраструктуры. Старую рабочую папку нельзя затем
пушить поверх очищенной истории: изменения переносятся в свежий clone.
Обновление удалённых веток выполняется с проверкой исходных SHA (lease),
без `git push --mirror` и без записи в `refs/pull/*`.

**Граница GitHub:** PR refs доступны только для чтения; чужие forks/clones
и кэшированные ссылки на старые SHA не очищаются обычным force push.
Их проверка и обращение владельца к GitHub Support — отдельная часть перехода.
Нельзя объявлять модель полностью недоступной, пока эти пути не закрыты.
Support не обещает удалять любые материалы по процедуре удаления секретов.
[Документация GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

**Уточнение владельца от 24 октября:** остаточный доступ через старые PR refs
принят и не блокирует работу над установщиком или его выпуск. Обращение
в Support и дополнительная очистка истории в текущий объём не входят.
Сохраняется требование исключать исходные материалы из новых публичных файлов
и поставки. Следующему агенту — [инструкция по установщику](installer-agent-handoff.md).

## Проверки и оставшийся этап

- Проверки исходников работают по отслеживаемым файлам: игнорируемая локальная
  модель допустима, отслеживаемая модель или GLB с другим именем — нарушение.
- Проверяются имена ZIP, дубликаты и коллизии регистра, пути Windows,
  выход из каталога, ссылки, полный перечень и хеши файлов.
- Ошибочный пакет не заменяет существующий Player; установка идёт в новый
  каталог и завершается только после полной проверки.
- Перед NSIS и в каталоге AppOnly отклоняются исходные модели, в том числе
  переименованные GLB. В установленную поставку входят notices и credit Kado.
- Готовность всего установщика не следует из проверки Unity. Открытые условия
  TTS/FFmpeg, лицензии, установленный состав и поведение Windows принимаются
  отдельно по [проверкам выпуска](release-checklist.md).

Автор модели указан как Kado / 柾木門 (@masakikado). По уточнению владельца
возражение относится к раздаче исходного VRM. Apache-2.0 на код не заменяет
условия модели. Упаковка усложняет извлечение; дополнительное шифрование
и обещание абсолютной неизвлекаемости в эту основу не входят.

# Навыки в разговоре

Ирис выбирает навык по смыслу текущего запроса и истории диалога. Пользователь
может спросить «что там с дата-центром Яндекса», не произнося «поищи».
Первый подключённый навык — `web_search`: он использует существующие
провайдеры, настройки, источники, кеш и бюджет поиска.

`create_reminder` подключён к текстовому и голосовому агентам. Инструмент
доступен только при явной просьбе пользователя напомнить; цитата из документа
или обычный план его не разрешают. Без точного времени возвращается уточнение.
Относительные сроки, «сегодня/завтра» и дни недели привязываются к текущим
часам; неоднозначное «в семь» требует уточнения. Один принятый пользовательский
ход имеет устойчивый ключ создания, поэтому повтор не создаёт второй срок.
Ответ об успешном создании разрешён только после сохранения реального плана.
Требования работающего Iris и разрешения Windows описаны в
[руководстве](user-guide.md#напоминания).

## Вызов и ответ

Для DeepSeek описания и схемы аргументов передаются в основной запрос через
штатный `tools` / `tool_choice=auto`. Модель сама выбирает функцию; backend
возвращает её результат сообщением `role=tool` с исходным `tool_call_id`.
Схема соответствует [function calling DeepSeek](https://api-docs.deepseek.com/guides/tool_calls/).
Решение не требует отдельного запроса к модели.

Поиск по сырой расшифровке и автоматический общий дайджест до этого решения
отключены для штатного DeepSeek. Короткие уточнения восстанавливаются по диалогу:
«то, что недавно произошло» не превращается в сетевой запрос «вот недавно новости».
Погода и время остаются контекстом окружения. Новостной экран и фоновый сбор RSS
сохраняют собственный путь.

Совместимые провайдеры без native tools могут вернуть внутреннюю команду:

```json
{"skill":{"name":"web_search","arguments":{"query":"Яндекс дата-центр последние события"}}}
```

В голосовом потоке тот же объект передаётся внутри `[[skill: {...}]]`.
Команда не попадает в чат и TTS. Backend проверяет имя, аргументы и доступность,
выполняет обработчик, затем передаёт результат модели для ответа в том же ходе.
Старые команды `web_search` поддерживаются для совместимости.

Для провайдеров без native tools сохранён прежний быстрый путь прямых запросов.
Если модель остановилась на «сейчас гляну», в том числе после комментария, backend один раз
поправляет ответ: восстанавливает команду по диалогу или получает уточнение.

Запрет интернета, выключенный поиск и реплики без задачи исключают веб-поиск.
Состояние проверяется и при исполнении: команда модели не отменяет ограничения.
Неизвестные навыки и неверные аргументы возвращают ошибку без выполнения.
Отмена хода отменяет обработчик; таймаут не оставляет его работать в фоне.
В метаданных текстового и голосового ответа сохраняются имя навыка, статус и длительность;
источники и фактические сетевые попытки остаются в `web_search`.

## Добавление навыка

Пошаговое руководство с примером навыка без поиска, подключением во всех
режимах и тестами — [разработка навыков](skill-development.md).

Контракт находится в
[`skills/runtime.py`](../apps/backend/app/skills/runtime.py). Новый навык состоит
из имени, краткого описания, Pydantic-модели аргументов, асинхронного обработчика,
проверки доступности и таймаута. Передайте объект `Skill` в параметре `skills`
при создании `CharacterAgent`. Для аргументов используйте `extra="forbid"` и
`strict=True`. Обработчик возвращает небольшой JSON-совместимый результат.

Доступность должна учитывать настройки и разрешения конкретного действия.
Текущий механизм не загружает Python-код, команды оболочки или сторонние
`SKILL.md` из ответа модели. Навыки регистрируются приложением. Coding Agent
пока остаётся в своём существующем маршруте с подтверждением применения.

## Расход

- Обычная беседа: один запрос к модели, без отдельного планировщика навыков.
- Навык по решению модели: команда, выполнение и один запрос для итогового ответа.
- Пропущенная команда с обещанием: один дополнительный запрос восстановления.

Для `web_search` модель придумывает короткую реакцию ожидания в поле
`acknowledgement` того же вызова. Это может быть междометие, напевание слогами
или короткая мысль в характере Ирис; списка готовых фраз нет. Модель учитывает
настроение беседы и серьёзность темы. Реакция остаётся локальной и не попадает
в поисковый запрос. Native-подводка также поддерживается; отдельного запроса
к модели для неё нет. Недавнее начало ответа повторно не произносится.

Реакция звучит один раз, если проверка длится дольше 0,8 секунды. При быстром
результате или отсутствии подходящей реакции сразу идёт итоговый ответ.
Отмена хода прерывает поиск и ожидающую генерацию; продолжение не повторяет
уже произнесённую реакцию. Вопрос о предмете выполняемой проверки подводкой
не считается.

Схема поиска поясняет точные названия, версии, коды ошибок, период и домены
первоисточников. `fallback_query` — другая формулировка того же вопроса,
в том числе на языке первоисточника. Уточнение может менять поисковые слова,
сохраняя названия, версии и цитаты; найденный соседний предмет не заменяет исходный.

В одном ходе выполняется одна операция навыка. Внутри веб-поиска сохранены
уточнения и чтение страниц с общим дедлайном 15 секунд. Это ограничивает
повторные вызовы, но не запрещает новый поиск в следующей реплике.
Стоимость дополнительного текста описаний зависит от модели; точная сумма
учитывается существующей телеметрией токенов, включая скрытые ответы.

Проверки: `tests/test_conversation_skills.py` — выбор без ключевых слов,
пример с Яндексом, команды по одному символу, второй зарегистрированный навык,
отмена, ошибки и отсутствие дополнительных вызовов в обычной беседе.
`tests/test_native_conversation_tools.py` проверяет настоящее API-представление
вызовов и результатов, сбор аргументов из потоковых фрагментов, сохранение ID,
объединение связанных поисков с общим бюджетом, отказ от частичного исполнения
смешанных вызовов и реплики из проблемного диалога.
